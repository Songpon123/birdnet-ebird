# Zoom H4essential → BirdNET / eBird: เดินอัดต่อเนื่องและกลับมาตรวจจาก MARK

ปรับปรุง: 22 ตุลาคม 2026 — อ้างอิงโค้ดในโฟลเดอร์นี้และคู่มือ H4essential / เฟิร์มแวร์ 2.30

คู่มือนี้สำหรับการเดินอัดยาวตลอดเส้นทาง (Continuous Transect) ด้วยไมค์ XY ติดเครื่อง และเพิ่ม RØDE NTG5 เพื่อเล็งเสียงนกบางตัวในอนาคต เป้าหมายคือเก็บต้นฉบับต่อเนื่อง หาเหตุการณ์ที่น่าสนใจกลับมาได้ และให้คนตรวจชนิดก่อนส่งคลิปไป `Ready/`

ดูวิธีใช้แอปทั่วไปใน [README หลัก](README.md)

## 2. ค่าประจำสำหรับเดินอัด

ตั้งค่าก่อนเริ่มเส้นทาง และลองอัด/ฟังจริงสั้น ๆ ก่อนออกงาน

| รายการ | ใช้ XY ตอนนี้ | เมื่อเพิ่ม NTG5 |
|---|---|---|
| แทร็ก | MIC เปิด; 1 และ 2 ปิด | MIC และ 1 เปิด; 2 ปิด |
| การต่อไมค์ | XY ติดเครื่อง | NTG5 ต่อ XLR Input 1; XY ยังใช้ได้ |
| `INPUT → 1 → Phantom` | Off | +48V On สำหรับ NTG5 |
| `INPUT → 2 → Phantom` | Off | Off |
| `INPUT → 1/2 → 1&2 Link` | Off | Off เพื่อเก็บ NTG5 เป็น mono |
| `REC → Format` | WAV | WAV |
| `REC → Sample Rate` | 48 kHz | 48 kHz |
| Bit depth เมื่ออัด WAV | 32-bit float ของเครื่อง | เหมือนเดิม |
| `INPUT → MIC → Mono Mix` | Off: เก็บ XY เป็น stereo | เหมือนเดิม |
| `INPUT → MIC → Plugin Power` | Off | Off; NTG5 ใช้ phantom ที่ XLR แทน |
| `REC → Rec Source` | Pre Mixer | Pre Mixer |
| `REC → AI Noise Reduction` | Off ทุกแทร็ก | Off ทุกแทร็ก |
| `REC → Mix File` | Off | Off เพื่อเก็บแทร็กแยก ไม่สร้างไฟล์ mix เพิ่ม |
| `REC → Metadata (iXML)` | Write | Write |
| `REC → Rec Start Tone` | Off | Off |
| `REC → Pre Rec` | On ได้; ที่ 48 kHz เก็บก่อนกดอัด 2 วินาที | เหมือนเดิม; ช่วยตอนเริ่มไฟล์ ไม่ใช่บัฟเฟอร์ย้อนหลังรอบ MARK |
| `Lo Cut` ของแทร็กที่ใช้ | เริ่ม Off; ลอง 80 Hz เมื่อมีเสียงครางต่ำจากลมหรือแรงเดิน | เลือกแยก MIC / Input 1 ตามเสียงที่ฟังจริง |
| `SYSTEM → Date/Time → Date Format` | YYMMDD | เหมือนเดิม |

ข้อแนะนำของงานนี้คือปิด AI Noise Reduction เพื่อเก็บเสียงนกเบา ๆ และบรรยากาศต้นฉบับไว้ก่อน ไม่ได้หมายความว่าทุกโหมดลดเสียงรบกวนจะลบเสียงนกเสมอไป

หัว XY เป็นมุม 90° คงที่ ไม่ต้องปรับมุมแคปซูล ใส่ขนกันลม ให้หัวไมค์พ้นผ้า/ซิป/สายกระเป๋า และลองเดินฟังว่าตำแหน่งยึดรับเสียงฝีเท้ามากเพียงใด การเพิ่ม Gain หรือใช้ 32-bit float ไม่แก้เสียงเสียดสี ลมกระแทก หรือเสียงนกที่ถูกเสียงอื่นกลบ

## 3. MARK มีประโยชน์อย่างไร

MARK คือจุดเวลาที่กดระหว่างอัด เครื่องอัดแสดงจุดนี้ตอนเล่นกลับและให้ข้ามไปฟังได้ คู่มือระบุสูงสุด **99 จุดต่อไฟล์** จึงควรใช้กับเหตุการณ์ที่มีความหมาย ไม่จำเป็นต้องกดทุกครั้งที่ได้ยินเสียงร้องซ้ำ

| เหตุการณ์ที่กด MARK | ประโยชน์ตอนกลับมาตรวจ | สิ่งที่ควรจดเพิ่ม |
|---|---|---|
| ได้ยินเสียงที่น่าสนใจแต่ยังไม่รู้ชนิด | กลับไปฟัง หาใน spectrogram และลอง `Ask BirdNET about the selection` | “เสียงสั้น 2 พยางค์ ด้านซ้าย” ดีกว่าใส่ชนิดที่ยังไม่แน่ใจ |
| เห็นนกพร้อมได้ยินเสียง | ช่วยเทียบเสียงกับภาพถ่ายและสิ่งที่เห็น | ชนิดที่เห็น, เวลา/ชื่อภาพ, ความมั่นใจว่าเสียงเป็นของตัวนั้น |
| ยก NTG5 เล็งแล้วได้ช่วงเสียงชัด | เลือกช่วงดีจาก `Tr1.WAV` โดยยังเก็บ XY ทั้งเส้นทางไว้ | เริ่มเล็งเมื่อไร ทิศทาง และช่วงที่หยุดเดิน |
| ได้ยินชนิดที่ BirdNET อาจพลาด | ทำรายการช่วงที่คนควรตรวจ แม้ไม่มีคลิปจาก AI | เสียงที่คาดไว้และหลักฐาน; ไม่ใช้ชื่อที่คาดเป็นผลยืนยัน |
| รถผ่าน ลมแรง คนคุย หรือหยุดเดิน | อธิบายว่าช่วงนั้นตรวจเสียงนกได้ยากหรือสภาพการเก็บข้อมูลเปลี่ยน | ประเภทเหตุการณ์และเวลาเริ่ม/จบถ้าทราบ |
| ผ่านจุดสำคัญบนเส้นทาง | เชื่อมเหตุการณ์กับบันทึกภาคสนามและ GPS track | รหัสจุด/ช่วงทาง ไม่ถือว่า MARK มีพิกัดอยู่แล้ว |

MARK ไม่มีความหมายเรื่องชนิด จำนวนตัว ทิศทาง หรือพิกัดในตัวเอง ต้องมีบันทึกประกอบ และจุดที่กดมักช้ากว่าเสียงแรกเพราะต้องใช้เวลาสังเกต/หยิบเครื่อง

### วิธีใช้ตอนเดิน

1. เริ่มอัดต่อเนื่อง เมื่อมีเหตุการณ์สำคัญ เลือกไอคอน `MARK` บนแถบเมนูระหว่างอัด แล้วกด ENTER
2. ถ้าอยู่ใน HOLD ให้ปลดก่อนกด แล้วล็อกกลับเมื่อทำเสร็จ
3. จดชื่อไฟล์หรือเวลาเริ่มไฟล์ พร้อมเวลา MARK/เวลานาฬิกาและเหตุผลสั้น ๆ ไม่ต้องรู้ชนิดก่อนจึงจะกดได้
4. หากเครื่องแยกเป็นไฟล์ใหม่ ต้องระบุไฟล์หรือเวลาเริ่มไฟล์ใหม่ด้วย ตำแหน่ง `06:12` เพียงอย่างเดียวไม่พอระบุเหตุการณ์ตลอดทริป

ตัวอย่างบันทึกภาคสนามที่บันทึกในมือถือหรือไฟล์ข้อความได้:

```text
วันที่: 2026-10-22
เส้นทาง: route-A
เวลาเครื่องอัดเทียบมือถือ: เครื่องอัดช้า 2 วินาที
GPS track: route-A.gpx (เก็บไว้ประกอบภายหลัง; แอปยังไม่นำเข้า)

ไฟล์: 261022_060000_TrMic.WAV
MARK / ตำแหน่งในไฟล์ / เหตุผล
01 / 00:06:12 / เสียงไม่ทราบชนิด ด้านซ้าย หยุดเดินฟัง
02 / 00:18:30 / รถผ่าน เริ่มเสียงรบกวน
03 / 00:19:05 / รถพ้น กลับมาได้ยินนกชัด
```

เลข MARK เป็นตัวอย่าง ให้จดตามที่เครื่องแสดงจริง การบอกส่วนต่างนาฬิกาต้องระบุทิศทาง เช่น “เครื่องอัดช้า 2 วินาที” เพื่อคำนวณย้อนหลังไม่สลับเครื่องหมาย

### ใช้ MARK กับโปรแกรม

เครื่องเก็บ MARK ในไฟล์ WAV เป็น chunk มาตรฐาน `cue ` ต่อท้ายเสียง แอปอ่านเอง ไม่ต้องจดตำแหน่ง (แต่ยังต้องจดเหตุผล เพราะ MARK มีแค่เวลาและเลขลำดับ)
เปิด `Find sounds ▾ → Recorder flags…` ดูรายการทุกจุด กด `▶ Listen around the flag` หรือ `Add clip here…` ได้เลย รายละเอียดอยู่ใน [README หลัก](README.md) หัวข้อ Recorder flags
ขั้นตอนด้านล่างเป็นวิธีทำเองทีละขั้น ยังใช้ได้เช่นกัน

ตัวอย่าง: ไฟล์เริ่ม `06:00:00` และ MARK อยู่ที่ `00:06:12` หรือ 372 วินาที เวลานาฬิกาตามเครื่องอัดคือ `06:06:12` ถ้าอัดต่อเนื่องและเวลาเริ่มไฟล์ถูกต้อง

1. เปิดผลของไฟล์นั้นใน `Review clips` แล้วกด `✚ Add clip yourself…`
2. ตรวจช่อง `Recording` ว่าเป็นต้นฉบับที่ถูกต้อง สำหรับ NTG5 ต้องเลือก `Tr1.WAV` ไม่ใช่ `TrMic.WAV`
3. ใน `Go to` ใช้ตำแหน่งในไฟล์ เช่น `6:12` หรือเลือกโหมด clock time แล้วใส่ `06:06:12`
4. ย้อนฟังก่อนจุด MARK เช่นเริ่ม `6:02` แล้วดูต่อถึง `6:32` เป็นช่วงค้นหาเบื้องต้น; ขยายเพิ่มถ้าเสียงเริ่มเร็วกว่านั้น
5. ลากเลือกเฉพาะช่วงเสียงที่ต้องการและเผื่อหน้า/หลังตามเหมาะสม ขอคำใบ้จาก `Ask BirdNET about the selection` ได้
6. เมื่อระบุชนิดได้จึงเลือก Species และ `✚ Add clip to Review` จากนั้นฟังตรวจ ให้คะแนนคุณภาพ แล้ว Approve ตามขั้นตอนปกติ
7. ถ้ายังระบุไม่ได้ ให้เก็บบันทึก/ต้นฉบับไว้ก่อน ไม่ใส่ชนิดเดาเพื่อให้ผ่านขั้นเพิ่มคลิป

ช่วงก่อน/หลัง MARK เป็นเพียงบริเวณให้ค้นหา ไม่ใช่ขอบเขตเสียงนกจริง และ MARK ไม่ได้สั่งให้ BirdNET ลดเกณฑ์ความมั่นใจโดยอัตโนมัติ

คลิปที่เพิ่มเองใช้ `Origin = Manual` และไม่มีคะแนนความมั่นใจจากการตรวจพบอัตโนมัติ การมี MARK ไม่ควรเปลี่ยนคลิปนั้นเป็นผลตรวจพบของ BirdNET

## 4. เวลาไฟล์ การอัดต่อเนื่อง และ GPS

**ตั้งเวลา H4essential ให้ตรงมือถือก่อนเริ่มทุกทริป** เก็บเวลาเริ่มไฟล์และส่วนต่างนาฬิกาไว้ หากต้องเทียบกับกล้องให้เทียบนาฬิกากล้องด้วย

เวลาของเหตุการณ์ในไฟล์ที่อัดต่อเนื่องคำนวณจาก:

```text
เวลาตามเครื่องอัด = เวลาเริ่มไฟล์ + ตำแหน่งเสียงในไฟล์
เวลาที่เทียบมือถือ = เวลาตามเครื่องอัด + ส่วนต่างที่ตรวจวัด
```

ข้อที่ควรตรวจเป็นพิเศษ:

- **Pause:** เครื่องข้ามช่วงเวลาที่พักและใส่ MARK เมื่ออัดต่อ ดังนั้น MARK บางจุดอาจมาจากการ resume ไม่ใช่คนได้ยินนก โปรแกรมยังไม่ชดเชยช่องว่างจาก Pause สูตรเวลาเริ่ม + offset หลังพักจึงอาจผิด ควรอัดต่อเนื่องสำหรับ transect นี้
- **ไฟล์เกิน 2 GB:** คู่มือระบุว่าเครื่องสร้างไฟล์/โฟลเดอร์ใหม่แล้วอัดต่อโดยเสียงไม่ขาด เก็บทุกส่วนไว้และตรวจเวลาเริ่มของแต่ละส่วน อย่าใช้เวลาเริ่มไฟล์แรกกับทุกส่วน
- **Pre Rec:** ที่ 48 kHz มีเสียงก่อนกดอัดได้ 2 วินาที ควรทดสอบกับไฟล์จริงว่า timestamp และ MARK อ้างอิงตรงกับเสียงอย่างไร ก่อนใช้เทียบเวลาอย่างละเอียด ไม่บวก/ลบ 2 วินาทีเองทุกไฟล์
- **ชื่อไฟล์:** ตัวอย่างชื่อเครื่องแบบ YYMMDD คือ `261022_060000_TrMic.WAV` ตัวพาร์สชื่อไฟล์ปัจจุบันคาดปี 4 หลัก จึงไม่ควรพึ่งชื่อแบบนี้อย่างเดียว ตรวจ metadata และช่อง Recording details; ถ้าอ่านไม่ครบให้กรอกวันที่/เวลาเริ่มเอง เก็บต้นฉบับชื่อเดิมไว้
- **Metadata:** การเปิด `iXML = Write` ไม่รับประกันว่าโปรแกรมอ่านได้ทุกฟิลด์หรืออ่าน MARK ได้ ควรตรวจวันเวลาที่แอปแสดงกับเครื่องจริงหนึ่งไฟล์ก่อนใช้ทั้งชุด
- **GPS:** เก็บ track จากมือถือพร้อมเวลาและเขตเวลาไว้ พิกัดเริ่มเดินเป็นข้อมูลคนละอย่างกับตำแหน่งตอนกด MARK หรือจุดที่ได้ยินเสียง แอปยังไม่จับคู่ GPX ตามเวลาให้อัตโนมัติ
- **ความหมายของตำแหน่ง:** GPS บอกตำแหน่งผู้บันทึก ไม่ใช่ตำแหน่งนก ระยะ/ทิศของนกต้องมีข้อมูลสังเกตเพิ่ม

ถ้า GPX ใช้เวลา UTC และเครื่องอัดตั้งเวลาท้องถิ่น ต้องแปลงให้อยู่ฐานเวลาเดียวกันก่อนจับคู่ และไม่จับคู่ข้ามช่วงที่ไม่มีข้อมูล GPS โดยเงียบ ๆ

สำหรับ transect ที่ใช้วิเคราะห์เชิงสำรวจ ควรจดการหยุดเดิน ระยะเวลา สภาพลม/ฝน และช่วงเสียงรบกวนด้วย การมีหรือไม่มีคลิป BirdNET ไม่เท่ากับมีหรือไม่มีนก และจำนวนคลิป/MARK ไม่ใช่จำนวนตัวนก

## 5. ใช้ XY คู่กับ NTG5

แนวทางที่แนะนำเมื่อมี NTG5 คือเปิด MIC + Input 1 ตั้งแต่ก่อนเริ่มเดิน อัดแยกตลอดเส้นทาง แล้วใช้เฉพาะช่วง NTG5 ที่เล็งได้ดีภายหลัง การใช้เฉพาะช่วงที่สนใจจึงไม่จำเป็นต้องเปิด/ปิดแทร็กระหว่างอัด

- `TrMic.WAV`: XY stereo เป็นบันทึกบรรยากาศเส้นทางและแหล่งเสียงให้ย้อนค้น
- `Tr1.WAV`: NTG5 mono เป็นเสียงจากทิศที่เล็ง เก็บต้นฉบับไว้อีกแทร็ก
- เมื่อได้ยินตัวที่สนใจ หยุดเท้า ยก NTG5 เล็ง นิ่ง แล้วกด MARK/จดเวลา ไม่ต้อง Pause แทร็ก XY
- หยุดฟัง/เล็งเป็นส่วนหนึ่งของบันทึกภาคสนามด้วย ถ้างานมีข้อกำหนดเรื่องความเร็วหรือเวลาหยุด ให้ทำตามระเบียบสำรวจของงานนั้น
- ใส่ shock mount และขนกันลม เก็บสายไม่ให้เสียดสีหรือดึงเครื่อง ทดลองเสียงขณะเดินก่อนใช้งานจริง
- เมื่อดูเหตุการณ์เดียวกันข้ามสองแทร็ก ให้เทียบเวลาเริ่มแต่ละไฟล์และตำแหน่งเสียงจริงก่อนใช้ offset เดียวกัน ห้ามสมมติว่า MARK ถูกเขียนเหมือนกันทุกแทร็กโดยยังไม่ได้ตรวจไฟล์
- หากวิเคราะห์ทั้งสองแทร็ก อย่านับจำนวนคลิปรวมเป็นจำนวนเหตุการณ์หรือตัวนก เลือกเสียงที่เหมาะกว่าสำหรับอัปโหลด และเก็บอีกแทร็กเป็นข้อมูลประกอบ

พื้นที่เสียงโดยประมาณที่ 48 kHz / 32-bit float และปิด Mix File: XY 2 ช่อง ≈ 1.38 GB/ชั่วโมง; XY + NTG5 รวม 3 ช่อง ≈ 2.07 GB/ชั่วโมง (GB ฐานสิบ ไม่รวมส่วนหัวไฟล์) เวลาการใช้แบตต้องทดสอบกับ phantom/หูฟัง/หน้าจอที่ใช้งานจริง

## 6. กลับจากภาคสนาม: ขั้นตอนที่ทำได้ตอนนี้

1. สำรองทั้งโฟลเดอร์การ์ด รวมทุกส่วนที่เครื่องแยกไฟล์ และเก็บบันทึกภาคสนาม/GPX/ภาพถ่ายไว้ด้วย
2. เลือก `TrMic.WAV` สำหรับวิเคราะห์ XY เป็นหลัก หากเลือกโฟลเดอร์ที่มี `Tr1`/`TrLR` ด้วย แอปไม่ได้เลือกเฉพาะ XY ให้ตามแผนงานนี้ ควรจัดสำเนาชุดวิเคราะห์ให้มีเฉพาะแทร็กที่ต้องการโดยคงต้นฉบับไว้
3. ตรวจ Recording details: วัน เวลาเริ่ม พิกัด และถิ่นอาศัย โดยเฉพาะช่วงทางที่มีหลายถิ่นอาศัย พิกัดเดียวไม่ใช่ track การเดิน
4. วิเคราะห์ตามปกติ แล้วตรวจคลิปใน Review ผลทุกชนิดจาก AI เป็นตัวเลือกให้ตรวจ
5. ย้อน MARK/บันทึกของคนอีกหนึ่งรอบ ไม่จำกัดการตรวจเฉพาะบริเวณที่ BirdNET พบ วิธีนี้ช่วยค้นหาช่วงที่ AI พลาดได้
6. ใช้ `Add clip yourself…` สำหรับเสียงที่ระบุได้แต่ไม่มีคลิป ใช้ Not sure กับคลิปที่ยังระบุไม่ได้ และให้ผลตรวจตามเสียงจริง
7. คัดลอกคลิปที่ตรวจแล้วเข้า `Ready/` ผ่าน Approve; เก็บไฟล์ต้นฉบับที่มี metadata และ MARK ไว้สำหรับย้อนตรวจ

ถ้าต้องย้ายหรือแปลงไฟล์ ให้ทำกับสำเนา การ export/ตัดต่ออาจเปลี่ยนเวลาเริ่มหรือละทิ้ง MARK; การเลื่อนไปยังตำแหน่งเสียงเดียวกันต้องอ้างอิงต้นฉบับที่จดไว้

## 7. แนวทางพัฒนา MARK ใน BirdNET ต่อไป — ยังไม่ได้ทำ

ลำดับที่ได้ประโยชน์กับงานนี้:

| ลำดับ | ความสามารถที่เสนอ | ประโยชน์ |
|---|---|---|
| 1 | อ่าน MARK และแสดงรายการพร้อมเวลาไฟล์/เวลานาฬิกา แล้วกดเปิดต้นฉบับตรงจุดนั้น | ลดเวลาหาจุดด้วยมือ ใช้ร่วมกับหน้าต่างเพิ่มคลิปที่มีอยู่ |
| 2 | แสดง MARK บน spectrogram และให้เลือกช่วงค้นหาก่อน/หลัง | ฟังย้อนหลังได้เร็วโดยไม่ต้องตัดคลิปทุก MARK |
| 3 | แสดงว่า MARK ใดมีคลิป BirdNET อยู่ใกล้แล้ว / ยังไม่มี | ทำคิว “คนได้ยิน แต่ AI อาจพลาด” ไม่ใช้ยืนยันว่าจุดนั้นมีนก |
| 4 | จับคู่เหตุการณ์ XY / NTG5 ของช่วงบันทึกเดียวกัน | สลับฟังเทียบและเลือกคลิป โดยไม่ทิ้งการอ้างอิงแทร็กต้นทาง |
| 5 | นำเข้า GPX และเทียบตำแหน่งตามเวลาเสียง | ช่วยดูตำแหน่งผู้บันทึกบนเส้นทาง พร้อมบอกช่วง GPS ขาด/เวลาไม่ตรง |

### สิ่งที่ต้องตรวจจาก WAV จริงก่อนเขียนตัวอ่าน

ยังไม่มีไฟล์ทดสอบจาก H4essential ที่มี MARK ในงานนี้ จึงยังไม่ยืนยันรูปแบบ chunk ที่เครื่องใช้จริง ตัวอ่านในอนาคตอาจต้องตรวจ RIFF `cue ` และข้อมูลกำกับ เช่น `LIST/adtl` หากมี แต่ห้ามถือว่าเครื่องใช้รูปแบบนี้โดยไม่มีตัวอย่าง

คู่มือหลักหน้า 138 ระบุว่า iXML `SYNC_POINT_LIST` ไม่ได้ถูกเขียน/อ่าน จึงไม่ควรสมมติว่า MARK อยู่ใน iXML เพราะเปิด `Metadata = Write` ต้องตรวจทั้งไฟล์เสียงและไฟล์ประกอบจริง

ชุดทดสอบจากเครื่องที่ควรเก็บ:

1. WAV สั้นที่อัดต่อเนื่อง มีเสียงอ้างอิงชัด ๆ และกด MARK 2–3 จุด จดเวลาที่หน้าจอแสดงไว้
2. ชุดเดียวกันที่เปิด XY + Input 1 เพื่อดูว่า MARK ปรากฏในไฟล์ใดและใช้ฐานเวลาเดียวกันหรือไม่
3. ไฟล์ที่เปิด Pre Rec เพื่อเทียบเวลาเริ่ม/MARK กับเสียงอ้างอิง
4. ไฟล์ทดสอบ Pause/Resume แยกจากงานจริง เพื่อแยก MARK จากการ resume และตรวจว่าข้อมูลใดอธิบายช่วงที่หยุดได้
5. ชุดที่เครื่องแยกไฟล์อัตโนมัติเมื่อเกินขนาด เพื่อตรวจการอ้างอิง MARK และเวลาเริ่มแต่ละส่วน

หลักในการพัฒนา:

- อ่าน metadata แบบไม่แก้ WAV ต้นฉบับ และคง `Source path`/ลายนิ้วมือของไฟล์ให้ตามกลับได้
- เก็บทั้งตำแหน่งดิบของ marker, หน่วย/ฐานอ้างอิง, sample rate, เวลา offset ที่แปลงแล้ว และไฟล์ต้นทาง หากรูปแบบใช้ sample offset จึงค่อยคำนวณ `วินาที = sample offset / sample rate`; ไม่ใช้จำนวนช่องคูณหรือหารเอง
- จุดที่อ่านได้ไม่ครบ/อยู่นอกความยาวไฟล์ต้องแจ้ง ไม่สร้างตำแหน่งเดา และต้องรองรับ WAV ที่ไม่มี MARK
- ใช้ MARK เพื่อเรียงลำดับการตรวจ ไม่ตัดช่วงที่ไม่ถูกมาร์กออกจากการวิเคราะห์ทั้งเส้นทาง
- เมื่อเพิ่มคลิปจาก MARK ให้คนเลือกขอบเขต/ชนิดและตรวจเสียงก่อน ไม่ Approve อัตโนมัติ
- เก็บเหตุผลของ MARK แยกจากผล BirdNET: ชื่อที่ผู้ใช้คาดไว้ไม่ควรกลายเป็นคำตอบอ้างอิงสำหรับวัดความแม่นโดยยังไม่ตรวจยืนยัน
- หากเชื่อม GPS ให้เก็บเขตเวลา/ส่วนต่างนาฬิกา/วิธีจับคู่และคุณภาพข้อมูล ระบุตำแหน่งนั้นว่าเป็นผู้บันทึก ไม่ใช่ตำแหน่งนก

จุดเชื่อมในโค้ดปัจจุบัน:

| ไฟล์ | ส่วนที่เกี่ยวข้อง |
|---|---|
| [field_audio_to_ebird.py](app/field_audio_to_ebird.py) | `_read_wav_meta`, `recording_context_preview`, `process_file`: metadata, เวลาเริ่ม, พิกัดต่อไฟล์; ยังไม่อ่าน MARK |
| [manual_window.py](app/manual_window.py) | `ManualClipWindow`: เปิดต้นฉบับตาม offset/clock time, ฟังและเลือกช่วง |
| [manual_clips.py](app/manual_clips.py) | `suggest` / `add_clip`: เดาเฉพาะช่วงและเพิ่มคลิป `Origin = Manual` |
| [review_store.py](app/review_store.py) | ผลตรวจและสำเนาใน Ready; การนำเข้า MARK ต้องไม่เปลี่ยนสถานะตรวจเอง |
